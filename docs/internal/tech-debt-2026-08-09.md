## Detail on the top tier

### 1–2. Vulnerable versions are in the production lock

`pip_audit` audits the **venv**, which is not what ships — so I checked
`services/api/requirements.lock`, which the API `Dockerfile` installs with `--require-hashes`. All
three vulnerable packages are pinned there at the affected versions:

```
pypdf==6.14.2          CVE-2026-71852, CVE-2026-71870   → fix 6.15.0
cryptography==49.0.0   PYSEC-2026-3552                   → fix 50.0.0
diskcache==5.6.3       PYSEC-2026-2447                   → no fix
```

**Why `pypdf` is Risk 4 rather than 2.** It is not a build-time tool. Seven shipped modules import
it — `doc_text.py`, `drawingset.py`, `pdfops.py`, `review.py`, `sheet_extract.py`,
`sheet_recover.py`, `stamps.py` — and several of those parse **PDFs a user uploaded**. That is
attacker-reachable input reaching a parser with two open CVEs. `cryptography` earns the same score
for a different reason: its single import site is `esign.py`, the digital-signature and PAdES seal
path, where a defect is a defect in a legal artefact.

**Effort 2, not 1**, because the lock is hash-pinned: bump, re-lock, re-hash, then run the full
backend suite (the PDF modules have real coverage, so a break will show).

### 3. The composer split ships a wrong drawing

Full analysis in [ADR-001](adr-001-sheet-composition.md). Summary: `_view_for_spec()` falls through
to plan for any unrecognised kind, so a sheet asked for `kind: "axon"` returns a **plan cut at
1.20 m carrying the caller's title**. Measured at v0.3.913. This is architecture debt that has
already become a correctness defect, which is why it outranks the larger structural items.

### 4. `register.ts` — pin it before it needs splitting

2,546 lines, unpinned, and the third-largest hand-written file in the tree. The `test_file_sizes.py`
entry for `qaSection.ts` records exactly this lesson: *"Pinned before it needs splitting rather than
after: a ratchet added at the point of pain only ratifies the pain."* Effort 1 — it is one line.

because paying it down means real decomposition (`SCALE-SEAM ⑨` estimates ~25 releases of one route
group each for `client.ts`).

## Checked and NOT counted as debt

Recording these matters as much as the register — an audit that only adds items is not verifying.

- **"`pypdf` is declared dev-only, so production is broken."** Investigated and **false**.
  `services/api` has no `requirements.txt`; the production manifest is `requirements.lock`, which the
  Dockerfile installs with `--require-hashes`, and `pypdf` is in it. Only the *comment* is stale
  (item 7).
- **"49 web suites don't import their namesake."** Raw count, misleading. 46 are named for a
  *concept* rather than a module — architecture gates like `no-import-cycles.test.ts`,
  `ties.test.ts`, `parity.test.ts` — which is the correct shape for them. Of the 3 remaining,
  `fileIO.test.ts` and `takeoff2d.test.ts` are deliberate source-assertions with the limitation
  stated in their headers, and `library.test.ts` exercises its mixin through `./client`, which is how
  that mixin is used. **Genuine test debt from this heuristic: zero.** The one real instance of the
  "asserts a reproduction" class was `wsReturn.test.ts`, fixed earlier today in v0.3.913.
- **npm dependencies:** `npm audit --omit=dev` → **0 vulnerabilities**.
